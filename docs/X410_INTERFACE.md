# X410 接入契约与准备清单

本轮实现 IQ 文件到公共接收观测的离线适配，用模拟采集验证接口；未操作 X410 或 UHD。
目前是单设备、单用户、单流、单发单收的有线回环设计。

## 模块边界

| 生产方 → 消费方 | 接口与内容 |
|---|---|
| 软件发射 → UHD 播放 | `export_waveform` 导出 `tx.h5`、`waveform.json` 与独立 `labels.npz` |
| UHD 接收 → 文件 | `write_capture` 保存原始 IQ、实际硬件参数、明确的帧索引及丢样事件 |
| 同步程序 → 离线前端 | 帧号、原始采样坐标起点、频偏、质量状态及同步来源 |
| 离线前端 → 接收机 | `load_observations` 返回 `ObservationBatch` 和接收质量记录 |
| 标签清单 → 评估／训练 | 按帧标识及布局标识匹配 TB 与实际 Mapper 比特，不传给推理接口 |

硬件控制应放在单独适配器中，后续提供 `probe()`、`send_burst(iq, metadata, start_time)`、
`receive(num_samples, start_time)`。其返回值必须包含实际回读参数和事件记录。
核心模型与离线文件读取不导入 UHD，硬件驱动环境单独记录版本。

## 波形与标签

`WaveformSpec` 包括 `layout_id`、逻辑采样率、FFT 点数、14 个逐符号 CP 样本数和子载波间隔。
`tx.h5` 为 schema 1，包含：

- `iq`：little-endian complex64，轴为 `[sample, channel]`；当前只支持一个通道。
- `frame_ids`、`frame_starts`：唯一帧标识及逻辑波形中的采样起点。
- 属性：完整波形配置及发送 IQ SHA256。

`labels.npz` 单独保存 `frame_ids`、`tb_bits`、`mapper_bits`。当前 TB 为 848 信息比特，
Mapper 标签为 1248 比特；数组尺寸从软件编码器生成，不在硬件程序中自行推断。
这些标签只能用于训练／评估，不能用于寻找未知接收帧或推理。

当前软件使用 720 ksample/s、48 点 FFT、4 样本 CP。这些是已验证的逻辑波形参数，
不是已确认的 X410 原生采样率或完整实测 NR 时域规范。硬件采样率以 UHD 回读为准；
通过显式重采样连接逻辑波形，记录滤波、幅度和采样率转换。正式冻结参数前检查带宽、
保护子载波、CP 和重采样失真，不能直接把软件参数写入设备后视作成功。
当前逻辑网格占满其采样带宽，适配器拒绝低于逻辑采样率的原始采集。
对 0.96、1.44、7.68 Msample/s 的模拟回环已通过帧号与 CRC 检查；重采样滤波仍会改变
频域幅度，不能把 CRC 通过解释为 IQ 逐点无损，实测波形仍需保护带和前端校准。

## 原始采集契约

HDF5 schema 1 包含 `iq`、`frame_ids`、`frame_starts`，以及 `waveform_spec`、`metadata`、
`events` 三组 JSON 属性。`frame_starts` 始终使用实际接收采样率下的原始样本坐标。

离线读取必需字段：

| 字段 | 含义 |
|---|---|
| `actual_rx_rate_hz` | UHD 实际接收采样率，正且有限 |
| `noise_variance_grid` | 前端补偿、重采样及幅度变换后，频域每个复样本的校准噪声方差 |
| `sync_source` | `provided`、`estimated` 或 `synthetic`，明确同步信息从何而来 |
| `frequency_offset_hz` | 待补偿频偏，缺省为 0 |
| `receive_amplitude_scale` | 原始接收样本到逻辑波形单位的幅度因子，缺省为 1 |

真实采集还必须保存：设备地址／序列号、UHD／FPGA 镜像版本、采集批次、请求和实际收发采样率、
频率与带宽、TX/RX 增益、通道及天线端口、时钟／时间源、设备时间、定时开始时间、样本数、
发送幅度、线缆及衰减器、噪声校准方法和接收前端设置。接收噪声不可直接用仿真配置值冒充。

`events` 的每个事件包含 `kind`、`start_sample`、`num_samples`。溢出、欠载、丢样或削顶
影响的帧应标为不可用于配对评估，不能靠移动标签索引来补齐。

## 离线前端行为

当前适配器接收已有的帧索引和同步参数，不实现盲帧检测：

1. 校验 IQ、布局、唯一帧号及参数，按原始采样坐标补偿频偏和幅度。
2. 按实际采样率进行显式有理重采样，再按帧索引提取完整波形。
3. 排除不完整帧以及与采集事件相交的帧，输出逐帧剔除原因。
4. 去除逐符号 CP，进行单位化 FFT 与频率排列。
5. 输出 `y[B,1,1,14,48]`、正的噪声方差、帧标识和布局标识，复用 B0/B1/B2 接收机。

保存的噪声方差必须已按前端变换校准，适配器不会根据发送真值估计噪声。
标签文件缺失时仍可执行推理与 CRC 检查；BER/BLER 必须另行提供匹配的标签。

运行 `scripts/x410_offline.py` 可生成含已知样本偏移、频偏及缺帧事件的模拟采集，验证上述接口。
该测试不证明实际射频链路或盲同步已经通过。

## 硬件同学需要提供／确认

- X410 的 UHD、MPM、FPGA 镜像、主时钟及驱动兼容情况；先记录 probe 输出。
- 主机和设备的控制／数据接口、地址、网络链路、可持续传输率和存储位置。
- 一路 TX 到一路 RX 的端口图、线缆和衰减器；依据设备规格核算增益与接收功率，先确认再发射。
- 请求与实际中心频率、采样率、带宽和端口配置；一台设备首轮采用明确记录的同源时钟与设备时间。
- 发射训练前导、帧号编码和同步程序。帧号需可由接收数据或可靠的采集时间关联得到。
- 首次 100–1000 帧的已知载荷、噪声参考区间、原始 IQ 与完整事件日志。
- 先用 B0 检查帧配对、同步和 CRC，再加入 B1/B2；按载荷与采集批次分开训练、验证、测试。

设备参数与镜像限制以 [X410 官方手册](https://files.ettus.com/manual/page_usrp_x4xx.html) 和实际回读为准。
